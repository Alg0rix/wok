# Wok implementation

Build a Go CLI controlling one persistent Chromium process per named profile.
Use direct CDP with one WebSocket dependency. Provide a separate, lightweight
HTTP viewer process per profile because /render must survive CLI exit.
Prefer chrome-headless-shell; fall back to installed Chromium/Chrome. Lightpanda
has no real graphical rendering and is unsuitable for the required viewer.

The earlier design is in ../design.md; this plan updates its working name to
Wok and adds the explicitly requested /render and benchmark scope.

## Units

1. CDP transport — internal/cdp. Multiplex requests, deadlines, subscription,
   disconnect propagation. Test protocol errors, cancellation and concurrency.
2. Browser actions — internal/browser. Tabs, navigation, accessibility refs,
   real input, snapshots, screenshots, eval, waits. Ref IDs cannot alias after
   document replacement. Test real browser integration through the CLI.
3. Render service — internal/render. Live HTML viewer, PNG, MJPEG, tabs,
   navigation, keyboard/mouse/wheel input; loopback only, origin/host checking.
   Exit when browser closes; explicit private-token shutdown endpoint.
4. Session lifecycle — internal/session. Private state, per-profile locks,
   detached browser/viewer, idempotent concurrent start, stale endpoint recovery,
   profile data persistence. Test isolated profiles and repeated starts.
5. CLI — internal/cli, cmd/wok. JSON output, errors, help, global options,
   lifecycle, browser actions, raw CDP; all commands usable from agent shells.
6. Benchmark and docs — bench. Compare subprocess-per-command Wok warm CDP,
   Playwright warm CDP, Playwright cold launch and resident Playwright controls.
   Same engine/workloads, local fixture, raw results, medians/p95, and memory
   separated from command latency. Include reproducible instructions.

## Execution

CE work; units 1–3 have non-overlapping ownership and execute in parallel.
Coordinator owns units 4–6, integration tests, whole-tree verification, review,
and git commits. No worker stages or commits shared files.

## Verification

Run go test -race ./..., go vet ./..., build binary, real subprocess integration
with two profiles, refs, screenshots, /render stream and input, stale sessions,
and benchmark against pinned playwright-core. Validate rendering with a real
browser client. Record unsupported platforms and frame limitations honestly.
